# Support

Meld is an open-source project. Support is provided through public documentation and issue tracking, with private reporting reserved for security and conduct concerns.

## Where to get help

- Start with the [README](README.md), the [book](docs/src/SUMMARY.md) and the [specifications](spec/README.md).
- Search [existing issues](https://github.com/enis1enis2/meld/issues) before opening a new one.
- For a reproducible defect, use the [bug report form](https://github.com/enis1enis2/meld/issues/new/choose).
- For a capability gap, use the [feature request form](https://github.com/enis1enis2/meld/issues/new/choose).
- For documentation problems, use the [documentation form](https://github.com/enis1enis2/meld/issues/new/choose).
- For a new language, use the [Lang Pack request form](https://github.com/enis1enis2/meld/issues/new/choose).
- For local setup or development questions, read [CONTRIBUTING.md](CONTRIBUTING.md).

## What to include

A useful report includes:

- the Meld commit or release candidate and the source of the binary;
- operating system, Rust toolchain and Python version where relevant;
- the smallest `.meld` file, Lang Pack or command line that reproduces the issue;
- expected behavior, observed behavior, and the full diagnostic output;
- whether the problem reproduces with `cargo test --workspace --all-targets --locked`.

## Private reports

- Security vulnerabilities: use the private advisory route in [SECURITY.md](SECURITY.md). Do not publish an unfixed vulnerability in an issue.
- Code of Conduct concerns: use the private reporting route in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Scope

There is no commercial support contract or guaranteed response time for general questions. Acknowledgement and triage are best-effort except where [SECURITY.md](SECURITY.md) states otherwise. Unverified third-party repackaging and locally built binaries are not covered by release signatures.
