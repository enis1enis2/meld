# Sandbox attestation matrix

This document records what each backend **claims to enforce right now**. It is descriptive only: `BackendProbe::require` and `BackendFeatures::can_enforce` remain the sources of truth, and a backend that cannot satisfy `EnforcementRequirements` must fail closed rather than spawn unconfined.

Authority is always `pack maximum ∩ runner constraints ∩ file default grant ∩ region grant`. Grants only narrow. Missing `[sandbox]` means network denied and an empty filesystem grant set.

## Explicitly unverified or constrained claims

- **Linux privileged runtime:** the namespace/seccomp/cgroup spawn test is ignored because it requires namespace privileges and writable cgroup v2. Host-side derivation/compilation tests do not prove kernel enforcement.
- **Landlock:** availability is probed, but enforcement is never claimed by `probe()`; `landlock_enforced` stays false. `landlock_available` must not be read as authority.
- **macOS:** the backend is compile-only on Linux; SBPL generation tests are macOS-only, and the runtime spawn test is ignored. `sandbox-exec`/SBPL support is an implicit platform assumption with Apple documentation/support caveats.
- **Windows:** compile-only on Linux; runtime tests are ignored. Job Objects are active, but AppContainer is not claimed. Deny-all policies intentionally fail closed rather than spawn without network/filesystem/syscall enforcement.
- **OCI:** optional `--features oci`; requires an absolute, canonicalized `MELD_OCI_RUNC`. The host trusts that runc binary. Runtime and confinement tests are ignored and require privileged runc. Spec-generation tests are not equivalent to a runtime proof.
- **T2/T3 are protocol/runtime layers:** T2 is a bounded stdio protocol and host-call gate, not an OS backend. T3 uses Wasmtime with strict limits and import rejection, but it does not replace the OS backend contract.
